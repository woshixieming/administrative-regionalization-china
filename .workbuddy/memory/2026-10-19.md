# 2026-10-19

## 项目优化评估（咨询，未改代码）

对已完成的数据管线 + 展示站做了一轮审查，基于代码与数据实测给出 9 项优化清单。

### 关键事实（供后续实施参考）

- **前端无 URL 状态同步**：五级选择全在 `useState`，刷新即丢、无法分享链接（`web/components/Explorer.tsx`）。
- **搜索只在已加载的当前列内过滤**（`Column` 组件 `filtered`），62 万村级实际不可检索。
- 分片体积：`l5` 342 个，平均 147KB / 中位 118KB / **最大 647KB（5001 重庆）**，合计 49.1MB；`l4` 最大 77KB。
- **项目非 git 仓库** —— 定时更新已在跑，却无版本历史，只能靠 5 份 `data/snapshots/pre-*` 回滚。视为最大隐患。
- 死代码：`scripts/fetch_nbs_fallback.py` 已被 `fetch_mumuy_fallback.py` 替代，README 已删但文件仍在。
- `validate.py` 挂接率只抽样 150/342 分片（约 44%）。
- 移动端：`xl` 以下退化为 1 列，5 张卡片纵向堆叠过长。

### 建议优先级

P0：数据版本化（git）→ URL 状态同步 → 全局搜索
P1：版本变更 diff / 数据导出 / 移动端布局
P2：分片按前 6 位再细化 / 清理死代码 / 校验改全量

### 补充：本机环境坑（已有记录，仍适用）

`npm run dev` 会因 Turbopack 删 `.next/dev/logs` 被 safe-delete 守卫拒绝而崩溃；
展示站改用 `npm run build` + `python3 -m http.server 3100` 服务 `web/out`。
